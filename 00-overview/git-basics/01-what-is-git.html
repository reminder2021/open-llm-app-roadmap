Git 是什么？

Git 是一个版本控制工具，用来记录代码的每一次修改。

通俗理解

想象你在写论文：

  • 你可能会保存多个版本：论文_v1.doc、论文_v2.doc、论文_最终版.doc、论文_最终版_真的最终版.doc
  • Git 就是帮你自动管理这些版本的工具
  • 你可以随时回到任何一个版本，不用担心改坏了

为什么需要 Git？

🔄 版本管理

每次修改都有记录，改坏了可以回退。

# 查看历史版本
git log

# 回退到某个版本
git checkout <版本号>

👥 团队协作

多人同时修改代码，不会互相覆盖。

# 拉取别人的代码
git pull

# 推送自己的代码
git push

☁️ 代码备份

代码存在 GitHub 上，电脑坏了也不怕。

# 代码已经自动同步到 GitHub
# 任何一台电脑都可以下载
git clone <仓库地址>

🌿 分支开发

可以同时开发多个功能，互不影响。

# 创建新分支
git checkout -b new-feature

# 切换回主分支
git checkout main

核心概念

理解这几个概念，Git 就学会了一半：

工作区（Working Directory）

你正在编辑的文件，就是工作区。

通俗理解：你正在写的文档。

暂存区（Staging Area）

准备提交的修改，先放在暂存区。

通俗理解：你准备保存的草稿。

本地仓库（Local Repository）

提交后的代码，存在本地仓库。

通俗理解：你电脑上的文档版本。

远程仓库（Remote Repository）

存在 GitHub 上的代码仓库。

通俗理解：云盘上的文档备份。

工作流程

修改文件 → 添加到暂存区 → 提交到本地仓库 → 推送到远程仓库

  工作区      git add       git commit        git push
 (编辑)    ──────────→  (暂存)  ──────────→ (本地)  ──────────→ (GitHub)

Git vs GitHub

Git

  • 是一个工具（软件）
  • 安装在你电脑上
  • 用来管理代码版本

GitHub

  • 是一个网站
  • 用来存储代码仓库
  • 方便团队协作
关系：Git 是工具，GitHub 是平台。你用 Git 这个工具，把代码上传到 GitHub 这个平台。
