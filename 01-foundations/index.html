数据处理基础

LLM 应用会不断在“文本、JSON、数据库记录、API 响应、模型输出”之间转换。数据处理能力会直接影响系统稳定性。

必须会的格式

  • JSON：API 请求响应、模型结构化输出、工具参数。
  • CSV：批量样本、评估集、标注数据。
  • YAML：配置文件、实验参数、训练配置。
  • 纯文本和 Markdown：知识库、Prompt 模板、日志摘要。

练习任务

任务 1：读取 Markdown 文件，统计字数、段落数和标题层级

这个练习对应后续 RAG 的文档解析。先从最简单的 Markdown 开始，理解“原始文档 → 可处理文本 → metadata”的过程。

查看示例 
from pathlib import Path
import re

def analyze_markdown(file_path: str) -> dict:
    # Path(...).read_text 比手动 open/read 更简洁，适合读取整个小文件。
    text = Path(file_path).read_text(encoding="utf-8")

    # Markdown 中通常用空行分隔段落，这里先做一个简单切分。
    paragraphs = [p.strip() for p in text.split("\n\n") if p.strip()]

    # 匹配 Markdown 标题，例如 "# 一级标题"、"## 二级标题"。
    headings = re.findall(r"^(#{1,6})\s+(.+)$", text, flags=re.MULTILINE)

    return {
        "chars": len(text),
        # \w+ 可以粗略统计英文单词和数字；中文场景下可先理解为基础示例。
        "words": len(re.findall(r"\w+", text)),
        "paragraphs": len(paragraphs),
        "headings": [
            # len(mark) 表示标题层级：# 是 1，## 是 2。
            {"level": len(mark), "title": title.strip()}
            for mark, title in headings
        ],
    }

if __name__ == "__main__":
    # 直接运行这个文件时，会分析当前目录下的 notes.md。
    result = analyze_markdown("notes.md")
    print(result)

可以新建一个 notes.md 文件测试。重点不是统计得多精确，而是学会把文档内容转换成结构化信息。

任务 2：读取 CSV 文件，把每行转换成 JSON

CSV 很常见：标注数据、评估集、用户反馈、训练样本都可能从表格来。这个练习帮助你熟悉批量数据转换。

查看示例 
import csv
import json
from pathlib import Path

def csv_to_json(csv_path: str, json_path: str) -> None:
    rows = []

    # newline="" 可以避免在不同系统上读取 CSV 时出现空行问题。
    with open(csv_path, "r", encoding="utf-8", newline="") as file:
        # DictReader 会把第一行当作字段名，每一行读成一个字典。
        reader = csv.DictReader(file)
        for row in reader:
            rows.append(dict(row))

    # ensure_ascii=False 可以让中文正常显示，不会被转成 \uXXXX。
    Path(json_path).write_text(
        json.dumps(rows, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

if __name__ == "__main__":
    # 输入 samples.csv，输出 samples.json。
    csv_to_json("samples.csv", "samples.json")

可以准备一个包含 question、answer 两列的 CSV。转换后的 JSON 后续可以直接用于评估或微调数据清洗。

任务 3：把一组文本样本保存成 JSONL

JSONL 是训练、评估和批处理里非常常见的格式。一行一个 JSON 对象，适合流式读取和大文件处理。

查看示例 
import json
from pathlib import Path

# 每个样本都包含任务说明、输入和期望输出。
# 这类格式后续可以演化成微调数据或评估数据。
samples = [
    {
        "instruction": "总结下面这段文字",
        "input": "LLM 应用开发需要关注数据、工具、评估和部署。",
        "output": "LLM 应用开发要重视工程闭环。",
    },
    {
        "instruction": "提取关键词",
        "input": "RAG 通过检索外部知识增强模型回答。",
        "output": "RAG，检索，外部知识，模型回答",
    },
]

def save_jsonl(items: list[dict], file_path: str) -> None:
    # JSONL 是“一行一个 JSON 对象”，适合大文件逐行读取。
    lines = [
        # ensure_ascii=False 保留中文可读性。
        json.dumps(item, ensure_ascii=False)
        for item in items
    ]

    # 最后补一个换行，是很多数据处理工具更喜欢的文本文件格式。
    Path(file_path).write_text("\n".join(lines) + "\n", encoding="utf-8")

if __name__ == "__main__":
    save_jsonl(samples, "train_samples.jsonl")

后续做 SFT 微调时，你会经常把样本整理成类似的 instruction/input/output 或 messages 格式。

任务 4：过滤空文本、超长文本和重复文本

数据清洗是 LLM 应用的基本功。脏数据会影响 RAG 召回、评估结果，也会影响微调质量。

查看示例 
def clean_texts(texts: list[str], max_length: int = 2000) -> list[str]:
    cleaned = []
    # set 用来记录已经出现过的文本，查询速度很快。
    seen = set()

    for text in texts:
        # strip 去掉首尾空白；split/join 把连续空白压成一个空格。
        normalized = " ".join(text.strip().split())

        # 跳过空字符串。
        if not normalized:
            continue

        # 跳过过长文本，避免后续处理成本过高。
        if len(normalized) > max_length:
            continue

        # 跳过完全重复的文本。
        if normalized in seen:
            continue

        seen.add(normalized)
        cleaned.append(normalized)

    return cleaned

if __name__ == "__main__":
    raw_texts = [
        "  LLM 应用开发  ",
        "",
        "LLM   应用开发",
        "RAG 可以接入外部知识。",
    ]
    print(clean_texts(raw_texts))

这里的去重用了简单规则。真实项目里可以继续加入繁简转换、标点归一化、相似文本去重等步骤。

HTTP 与 API 基础

后续无论是调用模型、调用工具，还是把你的能力暴露给前端，本质上都离不开 HTTP API。

请求

  • GET：读取资源。
  • POST：提交任务或生成内容。
  • Header：鉴权、内容类型、请求 ID。
  • Body：JSON 请求体。

响应

  • 200：成功。
  • 400：请求参数错误。
  • 401/403：未登录或无权限。
  • 429：限流。
  • 500：服务端错误。

LLM 场景下的 API 设计要点

  • 每个请求都应该有唯一 request_id，方便排查问题。
  • 耗时任务要考虑超时、取消和异步执行。
  • 错误响应要稳定，不要把内部异常直接暴露给用户。
  • 模型输出不可信，进入下一步前要校验。
  • API 返回结构尽量固定，方便前端和评估脚本使用。

FastAPI 必会内容

FastAPI 很适合 LLM 应用原型和中小型后端服务。它和 Pydantic 的结合能帮你减少大量参数校验代码。

最小服务示例

from fastapi import FastAPI
from pydantic import BaseModel, Field

# 创建 FastAPI 应用，title 会显示在 /docs 页面里。
app = FastAPI(title="Text Processor API")

# 请求模型：规定客户端必须传什么字段，以及字段是否合法。
class TextRequest(BaseModel):
    text: str = Field(min_length=1, max_length=8000)
    language: str = "zh"

# 响应模型：规定接口返回给客户端的数据结构。
class TextResponse(BaseModel):
    summary: str
    keywords: list[str]
    length: int

# response_model 会让 FastAPI 按 TextResponse 校验和展示返回结果。
@app.post("/process", response_model=TextResponse)
def process_text(payload: TextRequest) -> TextResponse:
    text = payload.text.strip()

    # 这是一个非常简单的关键词示例：按空格和中文标点切词，再去重。
    keywords = list(dict.fromkeys(text.replace("，", " ").replace("。", " ").split()))[:5]

    return TextResponse(
        summary=text[:80],
        keywords=keywords,
        length=len(text),
    )

需要掌握

  • 路由：@app.get、@app.post。
  • 请求模型和响应模型。
  • 路径参数、查询参数、请求体。
  • 统一异常处理。
  • 自动生成的 Swagger 文档：/docs。

异步、超时与流式响应

LLM 调用通常耗时较长，后续做流式输出、并发请求、工具调用时，异步能力会非常有用。

你需要理解

  • async def 和 await 的基本语义。
  • 用 httpx.AsyncClient 调用外部 API。
  • 为外部请求设置超时时间。
  • 用 FastAPI 返回流式响应。
  • 并发不是无限开，必须有限流和资源控制。
先能写同步版本，再改成异步版本。异步代码如果没有清晰边界，会让错误更难排查。

日志、配置与错误处理

LLM 应用很容易出现“偶尔答错、偶尔超时、偶尔格式坏掉”。没有日志，问题很难复现。

建议记录的字段

  • request_id：一次请求的唯一标识。
  • endpoint：调用了哪个接口。
  • latency_ms：耗时。
  • status：成功、参数错误、外部服务失败、内部异常。
  • input_length 和 output_length：避免记录完整敏感文本。
  • error_type：便于统计问题类型。

配置管理

  • 把端口、模型地址、API Key、超时时间放到环境变量。
  • 提供 .env.example，不要提交真实密钥。
  • 开发环境和生产环境使用不同配置。

第 3-4 天：Pydantic 与数据校验

为文本处理任务设计请求模型、响应模型和错误模型，练习字段长度、枚举值、默认值。

查看参考答案 
# app/schemas.py
from typing import Literal
from pydantic import BaseModel, Field

# 请求模型：所有进入接口的数据都先经过这里校验。
class TextProcessRequest(BaseModel):
    # 文本不能为空，最多 8000 个字符，避免一次请求太大。
    text: str = Field(min_length=1, max_length=8000)

    # Literal 限制只能传 "zh" 或 "en"。
    language: Literal["zh", "en"] = "zh"

    # ge 表示 greater or equal，le 表示 less or equal。
    max_keywords: int = Field(default=5, ge=1, le=20)

# 把统计信息单独建模，响应结构会更清晰。
class TextStats(BaseModel):
    chars: int
    paragraphs: int
    sentences: int

# 响应模型：前端、测试脚本和后续模块都可以依赖这个结构。
class TextProcessResponse(BaseModel):
    request_id: str
    summary: str
    keywords: list[str]
    stats: TextStats
    warnings: list[str] = []

# 错误响应也建议固定结构，不要每种错误返回不同格式。
class ErrorResponse(BaseModel):
    request_id: str
    error: str
    message: str

初学时先把“请求模型”和“响应模型”写清楚。后面接 LLM 时，模型输出也要用类似方式校验。

第 5-7 天：FastAPI 服务

实现 /health、/process、/batch-process 三个接口，并通过 /docs 测试。

查看参考答案 
# app/main.py
from uuid import uuid4
from fastapi import FastAPI

from app.schemas import TextProcessRequest, TextProcessResponse, TextStats

# 创建应用。启动后访问 /docs 可以看到自动生成的接口文档。
app = FastAPI(title="Text Processor API")

def extract_keywords(text: str, limit: int) -> list[str]:
    # 入门版关键词：用空格和中文句号逗号切分，再保持顺序去重。
    words = text.replace("，", " ").replace("。", " ").split()
    return list(dict.fromkeys(words))[:limit]

@app.get("/health")
def health() -> dict:
    # 健康检查接口通常用于确认服务是否正常启动。
    return {"status": "ok"}

@app.post("/process", response_model=TextProcessResponse)
def process(payload: TextProcessRequest) -> TextProcessResponse:
    text = payload.text.strip()

    # 每次请求生成一个 ID，排查日志时很有用。
    request_id = str(uuid4())
    warnings = []

    if len(text) < 20:
        warnings.append("文本较短，摘要可能不准确")

    return TextProcessResponse(
        request_id=request_id,
        summary=text[:120],
        keywords=extract_keywords(text, payload.max_keywords),
        stats=TextStats(
            chars=len(text),
            paragraphs=len([p for p in text.split("\n\n") if p.strip()]),
            sentences=text.count("。") + text.count("."),
        ),
        warnings=warnings,
    )

@app.post("/batch-process")
def batch_process(items: list[TextProcessRequest]) -> dict:
    # 复用单条处理逻辑。真实项目里可加入批量大小限制。
    return {
        "total": len(items),
        "results": [process(item) for item in items],
    }

# app/external.py
import httpx

async def fetch_url(url: str) -> dict:
    # 给外部请求设置超时，避免接口一直卡住。
    timeout = httpx.Timeout(5.0)

    # AsyncClient 用于异步 HTTP 请求，适合后续调用模型服务或工具 API。
    async with httpx.AsyncClient(timeout=timeout) as client:
        try:
            response = await client.get(url)

            # 如果状态码是 4xx/5xx，这里会抛出 HTTPStatusError。
            response.raise_for_status()
        except httpx.TimeoutException:
            return {"ok": False, "error": "timeout"}
        except httpx.HTTPStatusError as exc:
            return {
                "ok": False,
                "error": "bad_status",
                "status_code": exc.response.status_code,
            }
        except httpx.HTTPError as exc:
            return {"ok": False, "error": "http_error", "message": str(exc)}

    return {
        "ok": True,
        "status_code": response.status_code,
        "content_length": len(response.text),
    }
# app/main.py 中新增
from app.external import fetch_url

@app.get("/fetch")
async def fetch(url: str) -> dict:
    # FastAPI 支持 async 接口，适合等待外部服务返回。
    return await fetch_url(url)

# app/main.py 中加入简单耗时日志中间件
import logging
import time
from fastapi import Request

# 设置基础日志级别。真实项目可以进一步输出 JSON 日志。
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("text-processor")

@app.middleware("http")
async def log_requests(request: Request, call_next):
    # perf_counter 适合统计耗时。
    start = time.perf_counter()

    # call_next 会继续执行真正的接口处理逻辑。
    response = await call_next(request)
    latency_ms = round((time.perf_counter() - start) * 1000, 2)

    # 先记录方法、路径、状态码和耗时，避免日志里保存完整敏感文本。
    logger.info(
        "method=%s path=%s status=%s latency_ms=%s",
        request.method,
        request.url.path,
        response.status_code,
        latency_ms,
    )
    return response

实践项目：文本处理 API

做一个“文本处理 API”：接收一段文本，返回摘要、关键词、文本统计和结构化 JSON。先用规则实现，下一阶段再把规则处理替换为开源模型调用。

接口建议

  • GET /health：服务健康检查。
  • POST /process：处理单条文本。
  • POST /batch-process：批量处理多条文本。
  • GET /version：返回服务版本和配置摘要。

返回字段建议

  • summary：短摘要。
  • keywords：关键词列表。
  • stats：字符数、段落数、句子数。
  • warnings：输入过短、过长、疑似为空等提示。
  • request_id：请求 ID。

验收标准

  • 能用 uvicorn app.main:app --reload 启动。
  • 请求参数有 Pydantic 校验。
  • 错误时返回稳定 JSON，而不是直接抛异常页面。
  • 日志里能看到请求 ID、接口、耗时和错误类型。
  • 至少有 5 个测试用例：正常文本、空文本、超长文本、批量文本、非法参数。
  • README 能说明如何安装、启动、调用接口。
