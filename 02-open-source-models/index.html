学习目标

会选择模型

必须理解的概念

  • Base 模型适合继续训练，不适合直接聊天；Instruct/Chat 模型适合应用开发。
  • token 是模型处理文本的基本单位，不等同于汉字或英文单词。
  • 上下文窗口决定一次请求能放多少输入、历史消息和检索资料。
  • Safetensors 常见于 Hugging Face 模型；GGUF 常见于 llama.cpp/Ollama；AWQ/GPTQ 常用于量化部署。
  • Chat template 会把多轮消息转换成模型训练时熟悉的格式，格式错了会明显影响输出。
初学时不要追求最大模型。先用 7B/8B 级别把“下载、运行、调用、评估”链路跑通。

运行方式

Ollama

适合快速本地体验，命令简单，适合入门阶段。

Transformers

适合理解 tokenizer、model、chat template 和推理代码。

vLLM

适合部署服务，支持 OpenAI-compatible API、并发和高吞吐。

中文模型实践经验

中文场景下，选择对中文友好的模型可以显著提升效果。以下是几个主流中文开源模型的实践经验。

Qwen 系列（通义千问）

  • 推荐版本：Qwen2.5-7B-Instruct、Qwen2.5-14B-Instruct
  • 特点：中文能力强、工具调用支持好、上下文窗口大
  • 适用场景：通用对话、RAG、工具调用、代码生成
  • Ollama 快速体验：ollama run qwen2.5:7b

ChatGLM 系列

  • 推荐版本：GLM-4-9B-Chat
  • 特点：中文理解准确、推理速度快、社区活跃
  • 适用场景：中文问答、文本摘要、信息抽取
  • 注意事项：chat template 与其他模型不同，需特别处理

Yi 系列（零一万物）

  • 推荐版本：Yi-1.5-9B-Chat
  • 特点：双语能力强、指令遵循好
  • 适用场景：中英双语任务、创意写作

DeepSeek 系列

  • 推荐版本：DeepSeek-V2-Lite、DeepSeek-Coder-V2
  • 特点：代码能力强、推理能力突出
  • 适用场景：代码生成、数学推理、技术问答
选择建议：
  • 入门阶段先用 Qwen2.5-7B 或 GLM-4-9B，中文效果好且资源要求适中。
  • 需要工具调用能力优先选 Qwen 系列。
  • 需要代码能力优先选 DeepSeek-Coder。
  • 显存不足时考虑 4-bit 量化版本。

import httpx

def test_chinese_model(model_name: str, question: str) -> dict:
    """测试不同中文模型的回答质量"""
    url = "http://localhost:11434/api/chat"  # Ollama 默认端口

    payload = {
        "model": model_name,
        "messages": [
            {"role": "system", "content": "你是一个专业的中文助手，请用简洁准确的中文回答。"},
            {"role": "user", "content": question}
        ],
        "stream": False
    }

    response = httpx.post(url, json=payload, timeout=120)
    response.raise_for_status()
    return {
        "model": model_name,
        "answer": response.json()["message"]["content"]
    }

# 测试问题
test_question = "解释什么是 RAG，并给出一个实际应用场景。"

# 对比不同模型（需要先用 ollama pull 下载）
models_to_test = ["qwen2.5:7b", "glm4:9b", "yi:9b"]

for model in models_to_test:
    try:
        result = test_chinese_model(model, test_question)
        print(f"\n--- {model} ---")
        print(result["answer"][:200] + "...")
    except Exception as e:
        print(f"{model} 测试失败: {e}")

推理参数

  • temperature：越高越发散，越低越稳定。
  • top_p：控制候选 token 的概率范围。
  • max_tokens：限制最大输出长度。
  • stop：遇到指定字符串时停止生成。
  • stream：开启流式输出，适合聊天体验。

import httpx

def chat_once(message: str) -> str:
    # 本地模型服务地址。不同工具的端口可能不同，按实际情况修改。
    url = "http://localhost:8000/v1/chat/completions"

    payload = {
        "model": "local-model",
        "messages": [
            {"role": "system", "content": "你是一个简洁、准确的中文助手。"},
            {"role": "user", "content": message},
        ],
        "temperature": 0.3,
        "max_tokens": 512,
    }

    response = httpx.post(url, json=payload, timeout=60)
    response.raise_for_status()
    data = response.json()
    return data["choices"][0]["message"]["content"]

if __name__ == "__main__":
    print(chat_once("用三句话解释什么是 RAG。"))

任务 3：记录模型调用耗时

后续做评估和部署时，质量之外还要关心延迟。

查看示例 
import time
import httpx

def timed_chat(message: str) -> dict:
    start = time.perf_counter()
    response = httpx.post(
        "http://localhost:8000/v1/chat/completions",
        json={
            "model": "local-model",
            "messages": [{"role": "user", "content": message}],
            "temperature": 0.2,
        },
        timeout=60,
    )
    latency_ms = round((time.perf_counter() - start) * 1000, 2)
    response.raise_for_status()
    return {
        "latency_ms": latency_ms,
        "answer": response.json()["choices"][0]["message"]["content"],
    }

print(timed_chat("解释 Base 模型和 Chat 模型的区别。"))

实践项目：本地聊天服务

在第一阶段 FastAPI 服务的基础上，增加 /chat 接口，底层调用本地开源模型。

参考答案

查看 FastAPI 示例 
from pydantic import BaseModel, Field
from fastapi import FastAPI
import httpx

app = FastAPI(title="Local LLM Chat API")

class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=4000)
    temperature: float = Field(default=0.3, ge=0, le=2)

class ChatResponse(BaseModel):
    answer: str

@app.post("/chat", response_model=ChatResponse)
async def chat(payload: ChatRequest) -> ChatResponse:
    # 把自己的 API 请求转换成本地模型服务需要的格式。
    model_payload = {
        "model": "local-model",
        "messages": [{"role": "user", "content": payload.message}],
        "temperature": payload.temperature,
    }

    async with httpx.AsyncClient(timeout=60) as client:
        response = await client.post(
            "http://localhost:8000/v1/chat/completions",
            json=model_payload,
        )
        response.raise_for_status()

    content = response.json()["choices"][0]["message"]["content"]
    return ChatResponse(answer=content)

验收标准

  • 能通过 HTTP 调用本地开源模型。
  • 支持配置 temperature 和最大输出长度。
  • 记录请求耗时和失败原因。
  • 能对比至少 2 个模型或 2 组参数。

推荐资料

  • Ollama 官方文档：适合快速本地运行和调用模型。
  • vLLM OpenAI-compatible Server：学习如何把开源模型部署成兼容 OpenAI 风格的 API。
