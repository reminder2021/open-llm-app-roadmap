RAG 知识库问答

RAG 的核心不是“把文档塞给模型”，而是把文档切好、检索准、上下文组织清楚，并让答案可追溯。

建议周期：3-5 周产出：带引用的知识库问答系统重点：召回、引用、防幻觉

本阶段模块

完整流程文档切分检索与重排答案生成练习任务实践项目实战案例推荐资料返回主页

完整流程

  1. 加载文档：PDF、Markdown、HTML、Word。
  2. 清洗文本：去页眉页脚、目录、重复空白。
  3. 切分 chunk：保留标题、页码、来源。
  4. 生成 embedding：把 chunk 转成向量。
  5. 写入向量库：保存文本、向量和 metadata。
  6. 问题检索：召回相关 chunk。
  7. Rerank：重新排序，提高上下文质量。
  8. 生成答案：只基于上下文回答，并给出引用。

文档切分

切分太小会丢上下文，切分太大会召回不准。初学建议先从固定长度切分开始，再升级为按标题和段落切分。

查看切分示例 
def chunk_text(text: str, chunk_size: int = 500, overlap: int = 80) -> list[str]:
    # overlap 用来保留相邻片段之间的上下文连续性。
    chunks = []
    start = 0

    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end].strip()
        if chunk:
            chunks.append(chunk)
        start = end - overlap

    return chunks

print(chunk_text("很长的文档内容" * 100, chunk_size=100, overlap=20)[:2])

检索与重排

  • 向量检索适合语义相近的问题。
  • 关键词检索适合专有名词、编号、术语。
  • 混合检索通常比单一路径更稳。
  • Rerank 可以把召回结果重新排序，减少无关上下文进入模型。

答案生成

生成 Prompt 要明确要求：只能基于上下文回答、没有答案就说不知道、必须列出引用来源。

请只基于【参考资料】回答问题。
如果资料中没有答案，请回答“根据当前资料无法判断”。
回答后列出引用来源，格式为 [文件名 - 段落编号]。

def keyword_search(query: str, chunks: list[Chunk], top_k: int = 3) -> list[Chunk]:
    query_terms = set(query.lower().split())

    def score(chunk: Chunk) -> int:
        text_terms = set(chunk.text.lower().split())
        return len(query_terms & text_terms)

    # 按分数从高到低排序，只返回前 top_k 个。
    ranked = sorted(chunks, key=score, reverse=True)
    return ranked[:top_k]

for item in keyword_search("RAG 检索", chunks):

    blocks = []

def extract_pdf_with_structure(pdf_path: str) -> list[dict]:
    """提取PDF内容，保留页码和结构"""
    pages = []
    with pdfplumber.open(pdf_path) as pdf:

            tables = page.extract_tables()
            pages.append({

                "tables": tables,
                "source": Path(pdf_path).name
            })

常见挑战与解决方案

挑战1：表格数据

技术文档中的参数表格容易被切碎

方案：检测表格边界，整体作为单个chunk，或转为Markdown格式

挑战2：专业术语

通用Embedding模型对领域术语理解不足

方案：混合检索（向量+关键词），或微调Embedding

挑战3：多版本文档

产品迭代导致文档有多个版本

方案：metadata中记录版本号，检索时过滤版本

挑战4：长文档

上百页的技术手册检索效率低

方案：建立层级索引（文档→章节→段落）

def extract_table_as_markdown(table: list[list]) -> str:
    """将表格转为Markdown格式，保持结构完整"""
    if not table or len(table) < 2:
        return ""

    headers = table[0]
    rows = table[1:]

    md_lines = []
    md_lines.append("| " + " | ".join(str(h) for h in headers) + " |")
    md_lines.append("| " + " | ".join(["---"] * len(headers)) + " |")
    for row in rows:
        md_lines.append("| " + " | ".join(str(cell) for cell in row) + " |")

    return "\n".join(md_lines)

混合检索策略详解

展开查看混合检索实现

单一检索方式各有局限，混合检索能取长补短：

向量检索

✓ 语义相似
✓ 同义词匹配
✗ 精确术语弱

关键词检索

✓ 精确匹配
✓ 型号/编号
✗ 语义理解弱

混合检索

✓ 综合优势
✓ 更稳定
✗ 计算成本高

from rank_bm25 import BM25Okapi
import numpy as np

class HybridRetriever:
    def __init__(self, vector_db, chunks: list[str]):
        self.vector_db = vector_db
        self.bm25 = BM25Okapi([chunk.split() for chunk in chunks])
        self.chunks = chunks

    def search(self, query: str, top_k: int = 5,
               vector_weight: float = 0.7) -> list[dict]:
        # 向量检索
        vector_results = self.vector_db.search(query, top_k=top_k * 2)

        # 关键词检索
        bm25_scores = self.bm25.get_scores(query.split())
        bm25_top_idx = np.argsort(bm25_scores)[::-1][:top_k * 2]

        # 融合分数
        combined = {}
        for idx, result in enumerate(vector_results):
            chunk_id = result["chunk_id"]
            combined[chunk_id] = {
                **result,
                "score": result["score"] * vector_weight
            }

        for idx in bm25_top_idx:
            chunk_id = f"chunk_{idx}"
            if chunk_id in combined:
                combined[chunk_id]["score"] += bm25_scores[idx] * (1 - vector_weight)
            else:
                combined[chunk_id] = {
                    "chunk_id": chunk_id,
                    "text": self.chunks[idx],
                    "score": bm25_scores[idx] * (1 - vector_weight)
                }

        # 按融合分数排序
        results = sorted(combined.values(), key=lambda x: x["score"], reverse=True)
        return results[:top_k]

from abc import ABC, abstractmethod
from typing import AsyncIterator
import httpx

class LLMProvider(ABC):
    """LLM服务提供商基类"""

    @abstractmethod
    async def chat(self, messages: list[dict], **kwargs) -> str:
        pass

    @abstractmethod
    async def chat_stream(self, messages: list[dict], **kwargs) -> AsyncIterator[str]:
        pass


class DeepSeekProvider(LLMProvider):
    """DeepSeek API"""

    def __init__(self, api_key: str, base_url: str = "https://api.deepseek.com"):
        self.api_key = api_key
        self.base_url = base_url

    async def chat(self, messages: list[dict], **kwargs) -> str:
        async with httpx.AsyncClient() as client:
            response = await client.post(
                f"{self.base_url}/v1/chat/completions",
                headers={"Authorization": f"Bearer {self.api_key}"},
                json={
                    "model": kwargs.get("model", "deepseek-chat"),
                    "messages": messages,
                    "temperature": kwargs.get("temperature", 0.7),
                    "max_tokens": kwargs.get("max_tokens", 2000)
                }
            )
            return response.json()["choices"][0]["message"]["content"]

            )
            return response.json()["message"]["content"]


def create_llm_provider(provider: str, **kwargs) -> LLMProvider:
    """工厂函数：根据配置创建LLM提供商"""
    providers = {
        "deepseek": DeepSeekProvider,
        "glm": GLMProvider,
        "ollama": OllamaProvider,
    }
    if provider not in providers:
        raise ValueError(f"不支持的提供商: {provider}")
    return providers[provider](**kwargs)

class AccessControl:
    def __init__(self):
        self.permissions = {
            "product_a": ["customer_1", "internal"],
            "product_b": ["customer_2", "internal"],
        }

    def filter_chunks(self, chunks: list[dict], user_role: str) -> list[dict]:
        """根据用户权限过滤检索结果"""
        filtered = []
        for chunk in chunks:
            product = chunk.get("metadata", {}).get("product")
            if product and user_role in self.permissions.get(product, []):
                filtered.append(chunk)
        return filtered

常见问题FAQ

Q: 切分chunk大小怎么选？

建议从300-500字开始测试。太小会丢失上下文，太大会召回不准。技术文档通常按章节切分效果最好，避免在表格或参数列表中间切断。

Q: 检索返回多少条结果合适？

一般Top-K=5~10条，再用Rerank精选3~5条给模型。太多会增加token消耗和噪音，太少可能漏掉关键信息。

Q: 如何处理模型回答"不知道"的情况？

这是好事！说明防幻觉生效了。可以：1) 检查是否文档覆盖不足；2) 优化检索策略；3) 收集这类问题补充到文档中。

Q: 向量库选Chroma还是Qdrant？

开发阶段用Chroma（轻量、易用），生产环境用Qdrant（性能好、支持过滤）。数据量小（<10万条）两者差异不大。

Q: 如何评估RAG系统效果？

核心指标：1) 召回率（相关文档是否被召回）；2) 准确率（答案是否正确）；3) 忠实度（答案是否基于文档）。推荐用Ragas框架自动化评估。
