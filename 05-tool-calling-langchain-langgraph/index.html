工具调用、LangChain 与 LangGraph

工具调用让模型从“只会说”变成“能查询、计算、检索和执行”。这一阶段先手写工具调用，再学习 LangChain 和 LangGraph 的工程化编排。

建议周期：3-5 周产出：可控 Agent 助手重点：工具 Schema、状态、人工确认

本阶段模块

手写工具调用LangChainLangGraph练习任务实践项目推荐资料返回主页

先手写工具调用

不要一上来把工具调用交给框架。先理解循环：用户问题 → 模型选择工具 → 程序执行工具 → 工具结果回填 → 模型继续回答。

  • 工具名要短而明确，例如 search_docs、calculate。
  • 参数必须有 Schema，不能让模型随便拼字符串。
  • 工具执行失败时要返回结构化错误。
  • 写文件、发请求、删数据等操作需要人工确认。

再学 LangChain

LangChain 适合快速集成模型、Prompt、Retriever、Tool 和链式流程。学习重点是组件思想，而不是死记 API。

  • ChatModel：统一模型调用。
  • PromptTemplate：管理提示词模板。
  • OutputParser：解析结构化输出。
  • Tool：封装外部能力。
  • Runnable：把多个步骤组合起来。

重点学习 LangGraph

复杂 Agent 更适合 LangGraph：它用节点、边和状态描述流程，比传统自动 Agent 更可控。

  • 状态：保存用户问题、中间结果、工具结果。
  • 节点：每个节点做一件事，例如规划、检索、执行工具。
  • 边：根据条件决定下一步去哪里。
  • 人工确认：高风险操作暂停，等待用户批准。

练习任务

任务 1：定义工具 Schema

工具 Schema 是模型和程序之间的合同。

查看示例 
from pydantic import BaseModel, Field

class SearchDocsArgs(BaseModel):
    query: str = Field(min_length=1, description="用户要检索的问题")
    top_k: int = Field(default=3, ge=1, le=10, description="返回结果数量")

def search_docs(query: str, top_k: int = 3) -> dict:
    # 这里先写假数据，后续可以接 RAG 检索模块。
    return {
        "query": query,
        "results": [
            {"title": "RAG 入门", "content": "RAG 是检索增强生成。"}
        ][:top_k],
    }

args = SearchDocsArgs(query="什么是 RAG？", top_k=1)
print(search_docs(**args.model_dump()))

任务 2：实现工具注册表

用统一入口管理工具，方便后续做权限控制和日志。

查看示例 
TOOLS = {
    "search_docs": search_docs,
}

def run_tool(name: str, arguments: dict) -> dict:
    # 先检查工具是否存在，避免模型调用未授权工具。
    if name not in TOOLS:
        return {"ok": False, "error": f"未知工具: {name}"}

    try:
        result = TOOLS[name](**arguments)
        return {"ok": True, "result": result}
    except TypeError as exc:
        # 参数不匹配时返回结构化错误，方便模型或程序修复。
        return {"ok": False, "error": "参数错误", "message": str(exc)}

print(run_tool("search_docs", {"query": "工具调用", "top_k": 2}))

任务 3：为危险工具加入人工确认

Agent 的核心不是全自动，而是可控自动化。

查看示例 
DANGEROUS_TOOLS = {"send_email", "delete_file", "write_database"}

def need_confirmation(tool_name: str) -> bool:
    return tool_name in DANGEROUS_TOOLS

def plan_tool_call(tool_name: str, arguments: dict) -> dict:
    if need_confirmation(tool_name):
        return {
            "status": "waiting_confirmation",
            "tool": tool_name,
            "arguments": arguments,
            "message": "这个操作需要用户确认后才能执行。",
        }
    return run_tool(tool_name, arguments)

实践项目：个人工作助手

做一个能检索知识库、计算、查询 API、生成任务清单的助手。高风险操作必须暂停确认。

查看最小 Agent Loop 
def agent_loop(user_message: str, call_llm) -> str:
    # 第一步：让模型判断是否需要工具。这里约定模型返回 JSON。
    tool_plan = call_llm(f"判断是否需要工具，并输出 JSON: {user_message}")

    # 示例：真实项目中要用 Pydantic 校验 tool_plan。
    if tool_plan.get("tool"):
        tool_result = plan_tool_call(tool_plan["tool"], tool_plan["arguments"])
        if tool_result.get("status") == "waiting_confirmation":
            return tool_result["message"]

        # 第二步：把工具结果交回模型，让它生成最终回答。
        return call_llm(f"用户问题: {user_message}\n工具结果: {tool_result}\n请回答用户。")

    return call_llm(user_message)

验收标准

  • 至少支持 4 个工具。
  • 工具参数使用 Pydantic 校验。
  • 危险工具需要人工确认。
  • 记录每次工具调用的名称、参数、结果和耗时。
