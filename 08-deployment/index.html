部署与工程化

部署阶段的目标是把 Demo 变成稳定服务：配置清晰、日志可查、错误可恢复、权限可控制、模型服务可替换。

建议周期：3-6 周产出：可部署 LLM 应用重点：稳定、安全、可观测

模型服务

  • vLLM：适合 GPU 服务化和 OpenAI-compatible API。
  • Ollama：适合本地和小团队快速部署。
  • llama.cpp：适合 GGUF、CPU/Mac/边缘设备。
  • 量化：降低显存占用，但可能损失效果。
  • 多模型路由：简单任务用小模型，复杂任务用大模型。

工程能力

  • Docker/Compose：让服务一键启动。
  • 配置管理：模型地址、API Key、超时都用环境变量。
  • 日志：记录 request_id、耗时、错误类型、工具调用。
  • 缓存：Embedding 缓存、检索缓存、答案缓存。
  • 后台任务：文档解析、索引、评估适合异步执行。

安全边界

  • Prompt 注入不能只靠提示词解决，要靠权限和程序逻辑。
  • 工具白名单：模型只能调用你允许的工具。
  • 危险操作人工确认。
  • 不同用户的数据和知识库要隔离。
  • 不要在日志里记录完整密钥、隐私和敏感文本。

练习任务

任务 1：写 Dockerfile

先把 FastAPI 服务容器化。

查看示例
FROM python:3.11-slim

WORKDIR /app

# 先复制依赖文件，利用 Docker 缓存加速构建。
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app ./app

EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

任务 2：写 Compose 配置

把应用服务和模型服务拆开，后续更容易替换。

查看示例
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      # API 服务通过环境变量知道模型服务地址。
      MODEL_BASE_URL: "http://model:8001/v1"
      REQUEST_TIMEOUT: "60"

  model:
    image: vllm/vllm-openai:latest
    ports:
      - "8001:8000"
    # 真实部署时还需要配置模型路径、GPU 和 volume。

任务 3：读取环境变量配置

不要把模型地址和密钥写死在代码里。

查看示例
import os
from pydantic import BaseModel

class Settings(BaseModel):
    model_base_url: str = os.getenv("MODEL_BASE_URL", "http://localhost:8000/v1")
    request_timeout: int = int(os.getenv("REQUEST_TIMEOUT", "60"))

settings = Settings()
print(settings.model_base_url)

实践项目：部署 RAG + 工具助手

把知识库问答、工具调用和模型服务拆成可配置服务，并提供日志、鉴权和基础监控。

验收标准

  • 能用 Docker Compose 启动。
  • 应用服务和模型服务分离。
  • 所有密钥来自环境变量。
  • 有请求日志和错误日志。
  • 危险工具有人工确认流程。
