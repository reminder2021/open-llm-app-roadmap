部署与工程化

部署阶段的目标是把 Demo 变成稳定服务：配置清晰、日志可查、错误可恢复、权限可控制、模型服务可替换。

建议周期：3-6 周产出：可部署 LLM 应用重点：稳定、安全、可观测

本阶段模块

模型服务工程能力安全成本控制练习任务实践项目推荐资料返回主页

模型服务

  • vLLM：适合 GPU 服务化和 OpenAI-compatible API。
  • Ollama：适合本地和小团队快速部署。
  • llama.cpp：适合 GGUF、CPU/Mac/边缘设备。
  • 量化：降低显存占用，但可能损失效果。
  • 多模型路由：简单任务用小模型，复杂任务用大模型。

工程能力

  • Docker/Compose：让服务一键启动。
  • 配置管理：模型地址、API Key、超时都用环境变量。
  • 日志：记录 request_id、耗时、错误类型、工具调用。
  • 缓存：Embedding 缓存、检索缓存、答案缓存。
  • 后台任务：文档解析、索引、评估适合异步执行。

安全边界

  • Prompt 注入不能只靠提示词解决，要靠权限和程序逻辑。
  • 工具白名单：模型只能调用你允许的工具。
  • 危险操作人工确认。
  • 不同用户的数据和知识库要隔离。
  • 不要在日志里记录完整密钥、隐私和敏感文本。

成本控制与 Token 计费

LLM 应用的成本主要来自模型调用。理解 Token 计费、做好成本监控和优化，是生产部署的必备能力。

理解 Token 计费

  • 输入 Token：Prompt + 上下文 + 历史消息
  • 输出 Token：模型生成的回答
  • 计费单位：通常按千 Token 或百万 Token 计费
  • 中文特点：1 个汉字通常消耗 1-2 个 Token

成本优化策略

  • 模型选择：简单任务用小模型，复杂任务用大模型
  • Prompt 精简：减少不必要的上下文和示例
  • 缓存：相同问题复用历史回答
  • 批量处理：合并多个请求减少调用次数
建议：在开发阶段就加入 Token 统计，不要等到上线后才发现成本超出预期。
查看 Token 统计与成本计算示例 
import tiktoken
from dataclasses import dataclass

@dataclass
class TokenUsage:
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int

def count_tokens(text: str, model: str = "gpt-3.5-turbo") -> int:
    """统计文本的 Token 数量"""
    try:
        encoding = tiktoken.encoding_for_model(model)
        return len(encoding.encode(text))
    except KeyError:
        # 对于非 OpenAI 模型，使用通用估算
        # 中文约 1.5 字符/Token，英文约 4 字符/Token
        return len(text) // 2

def estimate_cost(usage: TokenUsage, model: str) -> dict:
    """估算调用成本（以 OpenAI 价格为参考）"""
    pricing = {
        "gpt-3.5-turbo": {"input": 0.0015, "output": 0.002},  # 每千 Token 价格（美元）
        "gpt-4": {"input": 0.03, "output": 0.06},
        "gpt-4-turbo": {"input": 0.01, "output": 0.03},
    }

    if model not in pricing:
        return {"error": f"未知模型: {model}"}

    prices = pricing[model]
    input_cost = (usage.prompt_tokens / 1000) * prices["input"]
    output_cost = (usage.completion_tokens / 1000) * prices["output"]

    return {
        "input_cost_usd": round(input_cost, 6),
        "output_cost_usd": round(output_cost, 6),
        "total_cost_usd": round(input_cost + output_cost, 6),
    }

# 使用示例
prompt = "请解释什么是 RAG？"
response = "RAG（检索增强生成）是一种结合检索和生成的技术..."

usage = TokenUsage(
    prompt_tokens=count_tokens(prompt),
    completion_tokens=count_tokens(response),
    total_tokens=count_tokens(prompt) + count_tokens(response)
)

print(f"输入 Token: {usage.prompt_tokens}")
print(f"输出 Token: {usage.completion_tokens}")
print(f"总 Token: {usage.total_tokens}")

cost = estimate_cost(usage, "gpt-3.5-turbo")
print(f"预估成本: ${cost['total_cost_usd']}")

import time
import logging
from fastapi import Request
from collections import defaultdict

logger = logging.getLogger("cost-monitor")

# 简单的内存统计，生产环境建议用 Redis 或数据库
usage_stats = defaultdict(lambda: {"requests": 0, "tokens": 0, "cost": 0.0})

async def cost_monitor_middleware(request: Request, call_next):
    """监控每个请求的 Token 使用和成本"""
    start_time = time.perf_counter()

    response = await call_next(request)

    # 从响应头或上下文中获取 Token 使用量
    # 这里需要你的应用在处理过程中记录这些信息
    if hasattr(request.state, "token_usage"):
        usage = request.state.token_usage
        endpoint = request.url.path

        usage_stats[endpoint]["requests"] += 1
        usage_stats[endpoint]["tokens"] += usage.get("total_tokens", 0)
        usage_stats[endpoint]["cost"] += usage.get("cost", 0.0)

        logger.info(
            "endpoint=%s tokens=%d cost=%.6f",
            endpoint,
            usage.get("total_tokens", 0),
            usage.get("cost", 0.0)
        )

    return response

def get_usage_report() -> dict:
    """获取使用统计报告"""
    return {
        "summary": {
            "total_requests": sum(s["requests"] for s in usage_stats.values()),
            "total_tokens": sum(s["tokens"] for s in usage_stats.values()),
            "total_cost": sum(s["cost"] for s in usage_stats.values()),
        },
        "by_endpoint": dict(usage_stats)
    }

WORKDIR /app

任务 3：读取环境变量配置

不要把模型地址和密钥写死在代码里。

查看示例
import os
from pydantic import BaseModel

class Settings(BaseModel):
    model_base_url: str = os.getenv("MODEL_BASE_URL", "http://localhost:8000/v1")
    request_timeout: int = int(os.getenv("REQUEST_TIMEOUT", "60"))

settings = Settings()
print(settings.model_base_url)

实践项目：部署 RAG + 工具助手

把知识库问答、工具调用和模型服务拆成可配置服务，并提供日志、鉴权和基础监控。

验收标准

  • 能用 Docker Compose 启动。
  • 应用服务和模型服务分离。
  • 所有密钥来自环境变量。
  • 有请求日志和错误日志。
  • 危险工具有人工确认流程。
