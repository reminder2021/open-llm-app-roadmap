一、什么是 Claude Code？

Claude Code 是 Anthropic 推出的命令行 AI 编程助手，它能深度理解整个代码库，提供智能代码生成、调试、重构等能力。与传统 IDE 插件不同，Claude Code 通过终端实现与现有工具的无缝融合。

🧠 代码理解能力

几秒钟映射整个代码库结构，理解项目依赖关系

📝 多文件智能编辑

跨文件修改和重构一气呵成，支持复杂重构操作

🔗 深度 Git 集成

自动解决合并冲突、生成 commit、创建 PR

💾 记忆系统

跨会话保持上下文，项目越用越懂你

🔌 MCP 扩展

连接外部服务，能力无限扩展

🤖 子代理系统

专业化的任务委派，支持多代理协作

二、安装与配置

2.1 系统要求

系统 要求
macOS macOS 10.15 (Catalina) 及以上
Windows Windows 10 及以上，需安装 WSL2
Linux 主流发行版均支持
Node.js 20.0.0 及以上版本

2.2 安装步骤

# NPM 全局安装（推荐） npm install -g @anthropic-ai/claude-code # 验证安装 claude --version # 直接运行（无需安装） npx @anthropic-ai/claude-code

2.3 认证方式

方式 适用场景 说明
OAuth 登录 个人用户 最简单，直接用 Anthropic 账号
API Key 企业用户/高级用户 更灵活，支持自定义配额
# 使用 API Key 认证 export ANTHROPIC_API_KEY="your-api-key-here" # 或者通过配置命令 claude config set apiKey your-api-key-here

2.4 配置文件位置

文件 路径 作用
全局配置 ~/.claude.json 用户级别设置
全局记忆 ~/.claude/CLAUDE.md 所有项目通用的记忆
项目配置 .claude/settings.json 项目级别设置
项目记忆 CLAUDE.md 项目根目录的记忆文件

三、CLAUDE.md 记忆系统

CLAUDE.md 是 Claude Code 的核心特性之一，它会在每次会话开始时自动加载到上下文中，让 Claude 了解你的项目和偏好。

3.1 创建方式

# 方式一：使用 /init 命令自动生成 /init # 方式二：手动创建 touch CLAUDE.md

3.2 推荐配置模板

# 项目概要 技术栈：Next.js 15 + tRPC + PostgreSQL 跑测试：pnpm test ## 代码风格 - 组件文件用 named export，不用 default export - 优先使用 ES modules (import/export) 语法 - 解构导入：import { foo } from 'bar' ## 全局约定 - 金额相关计算一律用整数表示"分"，禁止浮点数 - API 响应统一包裹在 { data, error } 结构里 - Commit message 用中文，格式：模块: 做了什么 ## 工作流 - 修改代码后务必运行 typecheck - 优先运行单个测试，而非整个测试套件

3.3 存放位置

  • 仓库根目录：最常见，命名为 CLAUDE.md 并提交到 git
  • 子目录：处理子目录文件时按需拉入
  • Home 文件夹：~/.claude/CLAUDE.md，适用于所有会话
💡 最佳实践：CLAUDE.md 内容控制在 30-150 行以内，只放 AI 需要在开口之前就知道的信息。规则放 CLAUDE.md，工作流放 Skills。

五、Hooks 钩子系统

Hooks 是 Claude Code 的事件驱动扩展机制，可以在关键交互节点插入自定义逻辑，实现自动化工作流。

5.1 Hook 类型一览

Hook 触发时机 常见用途
PreToolUse 工具执行前 阻止危险命令、验证文件路径、自动批准安全操作
PostToolUse 工具执行后 运行格式化工具、触发 linter、记录文件变更
SessionStart 会话开始时 注入 git 状态、加载 TODO 列表、设置环境上下文
UserPromptSubmit 提交提示时 注入项目上下文、验证请求、添加动态信息
Stop Claude 完成响应时 验证任务完成、运行测试、生成摘要
PermissionRequest 权限对话框出现前 自动批准测试命令、阻止访问敏感文件

5.2 配置示例

{ "hooks": { "SessionStart": [ { "type": "command", "command": "node .claude/hooks/session-context.mjs" } ], "PostToolUse": [ { "matcher": "Write|Edit", "type": "command", "command": "prettier --write $file_path" } ] } }

5.3 SessionStart Hook 示例

// .claude/hooks/session-context.mjs import { execSync } from 'child_process'; const branch = execSync('git branch --show-current').toString().trim(); const status = execSync('git status --short').toString().trim(); const log = execSync('git log --oneline -5').toString().trim(); console.log(` ## 当前环境 - 分支：${branch} - 最近提交： ${log} - 工作区状态： ${status || '干净'} `);
💡 最佳实践：
  • 设置合理的超时时间，避免 Hook 阻塞 Claude Code
  • 使用 JSON 格式通信，确保 Claude Code 能正确解析
  • 记录日志，方便调试和审计
  • 优雅降级：Hook 失败时不应阻断正常工作流

六、MCP 扩展配置

MCP（Model Context Protocol）允许 Claude Code 连接外部服务，扩展其能力边界。

6.1 配置文件位置

  • 项目级：.claude/settings.json
  • 用户级：~/.claude/settings.json

6.2 常用 MCP 服务器

MCP 服务器 功能 适用场景
filesystem 文件系统访问 跨目录文件操作
github GitHub API 集成 PR、Issue、代码审查
postgres PostgreSQL 数据库 数据库查询、Schema 管理
playwright 浏览器自动化 E2E 测试、网页抓取
figma Figma 设计稿 设计稿转代码

6.3 配置示例

{ "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"] }, "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"], "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" } } } }

七、自定义命令

通过自定义斜杠命令，可以将常用工作流封装成一键触发的操作。

7.1 创建方式

# 创建命令目录 mkdir -p .claude/commands # 创建命令文件 touch .claude/commands/deploy.md

7.2 命令文件格式

--- name: 部署到生产环境 description: 自动化 GitHub 和 Vercel 部署流程 --- ## 部署步骤 - [ ] Step 1: 运行 `pnpm run build` 检查构建 - [ ] Step 2: 创建 GitHub 私有仓库（可选） - [ ] Step 3: Push 代码到 GitHub - [ ] Step 4: 部署到 Vercel - [ ] Step 5: 验证部署结果 **重要**：只有 build 成功后才能继续

7.3 实用命令示例

/deploy

一键部署到生产环境

/review

代码质量审查

/test

运行测试并生成报告

/refactor

代码重构助手

八、权限管理

Claude Code 采用保守的权限策略，你可以根据需要自定义允许列表。

8.1 四种管理方式

方式 说明 适用场景
交互式允许 每次操作前询问 默认行为，最安全
会话级允许 当前会话内允许 临时信任
项目级允许 保存到项目配置 团队共享的规则
跳过权限 --dangerously-skip-permissions 个人项目，追求效率

8.2 配置允许列表

// .claude/settings.json { "permissions": { "allow": [ "Read", "Edit", "Bash(npm run build)", "Bash(npm test)", "Bash(git *)" ], "deny": [ "Bash(rm -rf *)", "Bash(curl *)" ] } }
⚠️ 安全提示：跳过权限模式仅限个人项目使用，生产环境或团队协作时务必启用权限检查。

九、子代理系统

子代理（Subagents）允许你将复杂任务分解给专业的代理处理，实现多代理协作。

9.1 内置子代理

代理 功能
planner 功能实现规划
architect 系统设计决策
code-reviewer 代码质量和安全审查
tdd-guide 测试驱动开发
build-error-resolver 构建错误解决

9.2 自定义子代理

# .claude/agents/security-reviewer.md --- name: security-reviewer description: 安全漏洞分析 tools: ["Read", "Grep", "Glob", "Bash"] model: opus --- 你是一个安全专家，专注于识别代码中的安全漏洞... 检查清单： 1. SQL 注入风险 2. XSS 漏洞 3. 硬编码密钥 4. 不安全的依赖

十、效率提升技巧

10.1 使用强调词提高遵循度

## IMPORTANT: 必须遵守的规则 - YOU MUST 在修改代码前创建备份 - NEVER 直接修改 node_modules - ALWAYS 使用 TypeScript 严格模式

10.2 提供清晰的上下文

❌ 模糊提示："帮我修复这个 bug"
✅ 清晰提示："src/api/users.ts 第 45 行的 getUser 函数在用户 ID 为 null 时会抛出 TypeError，请添加空值检查并返回 400 错误"

10.3 分步执行复杂任务

  • 将大任务拆解为小步骤
  • 每完成一步后验证结果
  • 使用 /compact 定期清理上下文
  • 善用 Esc 键中断不必要的操作

10.4 别名设置

# 在 ~/.zshrc 或 ~/.bashrc 中添加 alias cc="claude --dangerously-skip-permissions" alias ccd="claude --debug" # 使配置生效 source ~/.zshrc

10.5 常用工作流

🔍 代码探索

先让 Claude 理解项目结构，再进行修改

🧪 测试驱动

先写测试，再让 Claude 实现功能

🔄 迭代优化

逐步完善，每次只改一个小点

📋 检查清单

用 checklist 确保不遗漏步骤
